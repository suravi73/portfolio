Automated Semantic IoT Data Integration for Flexible Shop Floors Using WoT Thing Descriptions
Sep 2026
Sept. 2026
  • Built an ontology-aware LLM pipeline that automatically generates validated RML mappings from W3C WoT Thing Descriptions and CSV sensor data, replacing manual knowledge-graph authoring. Evaluated against hand-authored ground truth across 4 IoT scenarios (triple-level F1, TriplesMap completeness, ontology-usage metrics).
  • Architected a 4-stage constraint-narrowing pipeline (CSV analysis → TD semantic mapping → RML generation → error refinement), where each stage pre-computes facts (columns, ontology terms, auto-derived TriplesMap blueprint) to shrink the next call's decision space and suppress hallucination.
  • Implemented a two-layer self-repair loop: LLM-invoked validation tools (Turtle/SHACL) during generation via function calling, plus a Python outer loop that re-prompts with error-type-specific templates until a valid mapping is produced (inner 5 / outer 3 cycles).
  • Selected Qwen3.5 over Llama 3.3 for tool-calling reliability; validated with pySHACL against W3C RML Core shapes.
  • Eine ontologiebewusste LLM-Pipeline entwickelt, die automatisch validierte RML-Mappings aus W3C-WoT-Thing-Descriptions und CSV-Sensordaten erzeugt und die manuelle Erstellung von Knowledge Graphs ersetzt. Evaluiert gegen manuell erstellte Referenzdaten über 4 IoT-Szenarien hinweg (Triple-Level-F1, TriplesMap-Vollständigkeit, Ontologie-Nutzungsmetriken).
  • Eine 4-stufige, einschränkungsverengende Pipeline konzipiert (CSV-Analyse → semantisches TD-Mapping → RML-Generierung → Fehlerkorrektur), bei der jede Stufe vorab Fakten berechnet (Spalten, Ontologiebegriffe, automatisch abgeleiteter TriplesMap-Entwurf), um den Entscheidungsraum des nächsten Aufrufs zu verkleinern und Halluzinationen zu unterdrücken.
  • Eine zweischichtige Selbstkorrekturschleife implementiert: vom LLM aufgerufene Validierungstools (Turtle/SHACL) während der Generierung per Function Calling, plus eine äußere Python-Schleife, die mit fehlertypspezifischen Vorlagen erneut anfragt, bis ein gültiges Mapping entsteht (5 innere / 3 äußere Zyklen).
  • Qwen3.5 statt Llama 3.3 für zuverlässigeres Tool-Calling gewählt; mit pySHACL gegen die W3C-RML-Core-Shapes validiert.
Python Qwen3.5 RML RDF SHACL FastAPI

🤖 Insightbot: Intelligent Q&A Assistant

A context-aware Q&A assistant that lets users ask questions about any PDF document or website content.

Ein kontextbewusster Q&A-Assistent, mit dem Nutzer Fragen zu beliebigen PDF-Dokumenten oder Webseiteninhalten stellen können.

  • Powered by Groq's ultra-fast inference for chat, paired with Google Gemini embeddings for true retrieval-augmented generation (RAG) — documents are chunked, embedded, and only the most relevant excerpts are retrieved per question for accurate, source-grounded answers.
  • Technical: Python backend, Groq API integration, Google Gemini embeddings, PDF text extraction (PyPDF2), web scraping (BeautifulSoup), semantic chunking + vector retrieval (NumPy cosine similarity)
  • 🔗 View Code on GitHub
  • Angetrieben von Groqs ultraschneller Inferenz für den Chat, kombiniert mit Google-Gemini-Embeddings für echte Retrieval-Augmented Generation (RAG) — Dokumente werden in Chunks zerlegt, eingebettet, und pro Frage werden nur die relevantesten Ausschnitte abgerufen, für präzise, quellenbasierte Antworten.
  • Technisch: Python-Backend, Groq-API-Integration, Google-Gemini-Embeddings, PDF-Textextraktion (PyPDF2), Web Scraping (BeautifulSoup), semantisches Chunking + Vektorsuche (NumPy Cosine Similarity)
  • 🔗 Code auf GitHub ansehen

A dual-model forensic tool that analyzes digital artifacts to discover both obvious and hidden relationships using metadata clustering.

  • IT Admin Skill: Manages system-level dependencies (Exiftool) + Python wrapper integration.
  • Detail-Oriented: Handles edge cases like missing/corrupt metadata gracefully.

  • Zwei-Modell-Logik: Das Similarity-Modell clustert identische Felder; das Unique-Modell findet spärliche Zusammenhänge zwischen unterschiedlichen Feldern (z. B. tag='stolen' ↔ copyright='stolen').
  • IT-Admin-Kompetenz: Verwaltet systemnahe Abhängigkeiten (Exiftool) + Python-Wrapper-Integration.
  • Detailgenauigkeit: Behandelt Randfälle wie fehlende oder beschädigte Metadaten robust.
